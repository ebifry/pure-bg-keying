# 怎么验证抠得干不干净

> ⭐ **验证方法本身就是个坑。** 选错底色会得出"已经很好"的错觉。
> 这一页是踩出来的。

---

## 一、⭐⭐ 底色要选「能和错误对比出来」的

| 查什么 | 用什么底 | 为什么 |
|---|---|---|
| **漏抠 / 残留背景** | ⭐ **青色 `(0,220,255)` 或亮绿** | 透明显青、残留背景显灰 → **一眼可辨** |
| **色边 / 边缘观感** | **中灰 `(128,128,128)`** | 最接近桌面真实环境 |
| 整体交付目检 | 中灰 + 棋盘 | 棋盘看透明度，中灰看真实观感 |

### ⛔ 反例：用中灰底验证「漏抠」= 等于没验

残留的背景色本身**就是灰的**。合成到中灰底上：

- 透明区 → 显示中灰
- 残留背景 → 显示淡灰

**两者看起来几乎一样** → 你根本发现不了漏抠。
（我们就这么"验证通过"了一版，然后被用户一眼看出来。）

### ✅ 正确做法

```python
from PIL import Image

def on(img_rgba, color):
    bg = Image.new("RGBA", img_rgba.size, color + (255,))
    bg.alpha_composite(img_rgba)
    return bg.convert("RGB")

on(result, (0, 220, 255))     # ⭐ 验漏抠
on(result, (128, 128, 128))   # 验边缘观感
```

## 二、⛔ 别用「像素计数」下结论

**反例**：我们曾量出"残留污染像素 462px，占角色 0.18%"，判定"可接受" ——
**但在中灰底上放大一看，肉眼非常明显。**

**原因**：那些像素在**中性灰底上是高对比的**（比如洋红 / 紫色），
0.18% 的占比完全不能反映**视觉冲击**。

> ⭐ **像素计数只能用来"比较版本之间的相对变化"，不能用来判"能不能交付"。**
> **最终判据永远是：在正确底色上放大目检。**

---

## 三、⭐ 一秒安全检验：洞数检测

**用途**：加任何后处理（清理、滤波、形态学）之前 / 之后，判断**有没有把角色挖坏**。

```python
import numpy as np
from scipy import ndimage

def hole_stats(alpha: np.ndarray):
    """返回 (内部洞个数, ≥8px 洞个数, 洞总面积)"""
    mask = alpha > 128
    filled = ndimage.binary_fill_holes(mask)
    holes = filled & (~mask)              # 被角色包住、但是透明的区域
    lb, n = ndimage.label(holes)
    if n == 0:
        return 0, 0, 0
    szs = ndimage.sum(holes, lb, range(1, n + 1))
    big = szs[szs >= 8]
    return n, int(len(big)), int(big.sum()) if len(big) else 0
```

**怎么用**：

```
处理前：洞 13 个（≥8px 7 个，合计 3307px）
处理后：洞 21 个（≥8px 12 个，合计 5102px）   ⛔ 挖坏了 → 撤掉这个后处理
```

> ⭐ **为什么必须做这个检验**：
> 我们曾用"角色色板离背景最近 59，所以容差 30 安全"这种**推理**去担保安全 ——
> **结果在像素级挖出了洞。**
> ✅ **判据只能落在像素上，不能靠推理。**

**注意**：洞数**变多是坏**，但**少量洞是合法的** ——
比如"发丝与肩膀之间的空隙""豹纹领口内部"。
所以看的是**变化量**，不是绝对值。

## 四、完整验收清单

对每个交付的透明底素材：

- [ ] **模式是 RGBA**，且 `alpha` 确实有 0 和 255（不是全 255 的假透明）
- [ ] **青色底**：无灰色残留块（尤其**发丝缝隙 / 下巴两侧 / 辫子与肩之间**）
- [ ] **中灰底**：边缘无可见色边、发丝未被削细
- [ ] **棋盘底**：透明区正确（不是画上去的棋盘格纹理）
- [ ] **洞数**与处理前对比，没有意外增加
- [ ] **角色完整性**：眼睛高光、银饰、鞋带、拉链等细节还在
- [ ] **帧序列**：相邻帧对比，无闪烁（可用 `--temporal`）

---

## 五、帧序列的额外检查

| 检查 | 方法 |
|---|---|
| **帧间闪烁** | 逐帧 alpha 差分的均值/最大值；某帧突增 → 那一帧有问题 |
| **循环接缝** | 首帧 vs 末帧的 alpha 差；应 ≤ 内部差分的最大值 |
| **时空一致性** | 用 `--temporal 3` 后，孤立抖动应明显减少 |

---

## 六、一句话总结

> ⛔ **用中灰底验证漏抠 = 没验。**
> ⛔ **用像素计数判交付 = 会翻车。**
> ✅ **用青色底放大目检 + 洞数对比。**
