# 算法原理 —— 为什么是「交集」，以及各参数为什么是这个值

## 一、核心：两种方法取交集

```
前景 = 传统matting前景  ∩  语义模型前景
        （等价于：背景 = A背景 ∪ B背景 → 任何一方说是背景，就扣掉）
```

### 为什么两种方法互补

| 方法 | 判断依据 | 强项 | 弱项 |
|---|---|---|---|
| **传统 matting** | **颜色阈值** + 局部颜色统计 | ⭐ 对"颜色≈背景"的**小空隙**判得准 | 语义弱：形状上不合理的杂块可能被留下 |
| **语义模型**（isnet-anime）| **训练出来的语义** | ⭐ **主体轮廓**准、鲁棒 | **会漏小洞**：发丝缝隙、下巴两侧、辫子与肩之间 |

**关键观察**：两种方法的失败模式**几乎不重叠**。

- 模型漏的是**"主体内部的小背景块"** → 恰好是颜色阈值最擅长的地方
- 传统 matting 错的是**"主体边界的语义判断"** → 恰好是模型最擅长的地方

→ 所以**取交集**能让短板互相补上。

### 为什么是交集，不是并集

| 方案 | 含义 | 后果 |
|---|---|---|
| **前景取交集** ✅ | 任何一方说是背景就扣 | **干净**；两侧都"保守"→ 不会把背景留下 |
| 前景取并集 | 双方都说是背景才扣 | ⛔ 会留下"任意一方认成前景"的像素 → **漏抠** |

⭐ 本工具的目标是**"能扣多干净扣多干净"**，所以取**交集**。

> ⚠️ **术语提醒**：说"取并集"时一定要讲清是**前景**取并集还是**背景**取并集 ——
> 两者正好相反，很容易搞错。（我们就搞错过一次，代价是一轮返工。）

## 二、流程分解

```
输入 RGB
   │
   ├─ BG = 四角 40×40 的中值          ← 素材是纯色底，这个估计最稳
   │
   ├──────────────── A：传统 matting ────────────────
   │   d = |RGB − BG|₁
   │   m = 闭运算(d > THRESH)                        ← THRESH = 40
   │   trimap:  确定前景 = erode(m, 3)
   │            未知带   = dilate(m, 3) − 确定前景
   │            确定背景 = 其余
   │   α = estimate_alpha_cf(...)                    ← closed-form matting
   │   α = clip((α − 0.5) × 1.5 + 0.5, 0, 1)         ← 收窄
   │   F = estimate_foreground_ml(...)               ← ⭐ 这个 F 同时用作最终颜色
   │
   ├──────────────── B：语义模型 ────────────────
   │   α = rembg(isnet-anime, alpha_matting=True)
   │
   ├── ⭐ α = min(α_A, α_B)                          ← 前景取交集
   │
   ├── 清理 ≤30px 的非主体连通块
   └── 裁到角色 bbox + 60px 边距
```

## 三、参数为什么是这个值

| 参数 | 值 | 为什么 |
|---|---|---|
| `THRESH` | **40** | trimap 的"距背景"阈值。太小 → 前景核心过窄；太大 → 细发丝被判成背景 |
| `TRIMAP_ERODE` | **3** | 确定前景的腐蚀量。给"未知带"留出足够的宽度让 matting 求解 |
| `TRIMAP_DILATE` | **3** | 未知带的宽度。要覆盖抗锯齿的过渡区 |
| `ALPHA_NARROW` | **1.5** | ⭐ **刻意没设更大**。3.0 会把边做硬（过渡像素只剩 17%，出现锯齿感）；1.5 兼顾"压掉发雾"与"保留抗锯齿" |
| `AM_FG / AM_BG / AM_ERODE` | **240 / 10 / 8** | `alpha_matting` 的调参。`erode_size` 太小 → 边缘保留过多背景；太大 → 啃掉发丝 |
| `NOISE_MAX` | **30** | 主体外小碎块的上限。超过 30px 的块保留（可能是角色的合法小部件） |
| `CROP_MARGIN` | **60** | 输出裁到角色 bbox 后留的边距 |

## 四、背景色怎么选

### ⭐ 结论：**中性灰（或任意与角色色板有足够距离的纯色）即可**

**不要**为了抠图特意去出「洋红底 / 绿幕底」。

### 为什么

我们实测过一个反直觉的结果：

| 背景 | 分割质量 | 边缘观感 |
|---|---|---|
| **中性灰** | 略差（背景离角色近）| ⭐ **污染读作"阴影"，不可见** ✅ |
| **洋红** | ⭐ 更好（离角色最远）| ⛔ **边缘被染成可见的粉边** |

**原因**：背景色越饱和 / 离角色越远，**分割越容易**，但同时 ——
**角色边缘的抗锯齿像素会被背景染得越明显**。
因为那些像素是 `α·前景 + (1−α)·背景` 的混合，
背景是洋红时，混合出来就是**肉眼可见的粉边**；背景是中性灰时，混合出来是**淡灰**（读作阴影）。

> ⭐ **所以"背景色"是一个 trade-off，不是"越远越好"。**
> 而在用了**交集混合算法**之后，"分割质量"这一侧的收益差距被大幅缩小 →
> **中性灰反而是更优的选择**（代价只剩"边缘一圈不可见的淡灰"）。

### 判断某个背景色是否合适

算一下**角色主色板与该背景色的最小距离**：

```python
import numpy as np
bg = np.array([99, 99, 99])                       # 候选背景色
palette = [(219,215,209), (46,64,87), ...]        # 角色主色
print(min(np.linalg.norm(np.array(c) - bg) for c in palette))
```

- **≥ 150**：分割很轻松（但注意边缘染色是否可见）
- **60–150**：可用，交集算法能补
- **< 60**：⚠️ 偏近，传统 matting 那一路会明显变弱

## 五、帧序列为什么要做时域平滑

**问题**：语义模型是**逐图推理**的，相邻帧的 α 可能微抖 →
合成到桌面上会**闪**。

**注意分工**：
- **传统 matting 那一路是确定的**（同一帧输入 → 同一输出）
- **抖的是模型那一路**

**本工具的做法**：对最终 α 序列做**长度 k 的中值滤波**（`--temporal 3`）。
中值（而非均值）的好处是**不模糊边缘**，只抹掉孤立抖动。

⛔ **不要**用"逐帧跑模型"来做序列帧的最终 α —— 如果一定要用模型输出，
**必须在时域上做一致性处理**，否则闪烁几乎必然出现。
