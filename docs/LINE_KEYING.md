# 顺着勾线切 · Key by the Line Art

> 这一招不是我想出来的，是被一句外行话点醒的。
> 那天我调阈值调了一整天，对方看了一眼原图说：**「人物本身是有勾线的，顺着勾线切割其实会很干净的。」**

---

## 问题不在阈值，在"边界"根本不在那儿

先说我之前的思路有多理所当然：量背景色，算每个像素到背景的颜色距离，大于阈值的算角色。纯色底嘛，这有什么难的。

难的地方在于**边界那圈像素长什么样**。

动漫素材的边缘不是一刀切开的，是抗锯齿渲染出来的。从"完全是背景"到"完全是角色"之间，横着大概一到两个像素的过渡带，里面的颜色是 `α·角色 + (1−α)·背景` 的混合。我的阈值就落在那条带子里。

落在带子里意味着什么？意味着**我在一个没有正确答案的地方找正确答案**：

- 阈值紧一点 → 边界切在靠外，那圈混了背景色的像素算角色 → 留下一圈暗边
- 阈值松一点 → 边界切在靠内 → 开始吃角色，细结构先死

这就是那圈"暗边"的来源。它不是参数没调好，是**阈值法的边界位置天生就是模糊的**。

而勾线不一样。勾线是一条深色的、高对比的、有明确内外之分的线。它本来就被画在那儿。**那是一道现成的切割线。**

---

## 怎么把"顺着勾线"变成代码

工具有了：泛洪。

勾线是深色的，距背景远，泛洪过不去。所以从画面四边往里灌，灌不到的地方就是角色。

```python
passable = (距背景 < TOL_OUT)        # 可通行 = 颜色接近背景
从画面四边取连通域 → outside
角色 = ~outside                       # 勾线天然阻断了泛洪
```

这段话最大的好处是**参数不敏感**。实测同一段素材（768×1152，107 帧，背景 `(96,96,96)`），把 `TOL_OUT` 从 20 一路加到 65：

| TOL_OUT | 切出的角色像素 |
|---|---|
| 20 | 148825 |
| 65 | 143556 |

差 3.5%。因为泛洪的边界是**勾线**，不是阈值——阈值只负责"判断哪些像素能走"，而真正拦住它的是那条线。**参数只要落在"背景和勾线之间"这一大片区间里，结果都一样。**

这一点很舒服。它意味着这套东西换素材、换角色、换背景亮度，都不用重新标定。

---

## 第二个问题：角色**内部**也有背景

第一版我只做了上面那一步。交出去之后被打回来了，指着膝弯和辫子旁边：**这几块灰的是什么。**

是背景。角色手叉腰、辫子垂在肩上、腿弯起来的时候，会围出一些**封闭的空腔**，里面的背景色跟外面不连通，泛洪到不了，于是被整个当成角色留下了。

解法是再来一次泛洪，从空腔里面往外灌。但这一次有两个坑，都踩过。

**坑一：种子不能用几何质心。**

我第一版就是取每块候选的质心当种子。直到被指出：

> ⭐ **「封闭空间如果是月牙型/异形，不能放中间，泛洪一定要放在对应的背景颜色上。」**

月牙形的质心根本不在月牙里面，在它对面的角色肉上。从那儿泛洪，就把角色啃掉一块。

正确的做法是取**块内距背景最近的那个像素**当种子：

```python
dm = np.where(block, dist_bg, INF)
seed = argmin(dm)          # ⭐ 一定是"最像背景"的那个像素
```

种子距离实测在 0 到 4 之间（L1），也就是说它确实落在背景色上而不是过渡色上。这一步还有个副作用是自带守门：如果一块候选里最像背景的像素都不够像背景（距离大于 `SEED_MAX`），那这块根本不是空腔，整块不动。

**坑二：泛洪必须锁在角色内部那个掩膜里。**

不锁的话它会顺着自己刚切出来的抗锯齿带往外漏，一路漏到画面外。实测漏过一次 **73 万像素**，整张图几乎被清空。

## 软边怎么来的

二值掩膜边是硬的，直接出图会有锯齿。但软边不能随便做。

先说一个反直觉的：**不能直接用距离变换。**

我一开始写的是 `alpha = clip(dist/band + 0.5)`，看着很合理——离边界越远越不透明。跑出来量了一下，半透明像素占比 **0%**。原因很好懂：距离变换给的是整数距离，`1/2+0.5=1`、`0/2+0.5=0.5`，再往下就没有档了，二值化了。

现在用的是**先内缩 1 像素，再高斯模糊**。

为什么要内缩：泛洪停下来的位置是"第一个距背景 ≥ TOL_OUT 的像素"，那是抗锯齿带上背景混色还占九成的位置。**比理想的 50% 覆盖线还往外多留了大约一个像素的背景混色。** 内缩 1 像素正好把它压回去。

```python
m = binary_erosion(char, iterations=1)
alpha = gaussian_filter(m.astype(float), 0.8)
```

另外还有个 `defringe`：半透明带里的颜色不取原像素，取**最近实心像素的颜色**。只改颜色不改 α，所以不会削角色，效果是那圈灰读起来像阴影而不是脏边。

## 跟原来的 matting 路线是什么关系

不是替代，是分工。

| | 顺着勾线切 | 传统 matting（pymatting ∩ isnet-anime）|
|---|---|---|
| 靠什么找边界 | **勾线**（结构）| 颜色阈值 + 语义分割 |
| 硬边（人物、道具、描边插画）| ⭐ 干净，且参数不敏感 | 边界落在模糊带里 → 留暗边 |
| 发丝级细结构 | ⚠️ 细到没有勾线的地方就无从下手 | ⭐ 这才是它的主场 |
| 速度 | 0.2s/帧（768×1152，纯 CPU）| 秒级 |
| 需要模型 | 不需要 | 需要（isnet-anime 168MB）|

**素材上有勾线就用勾线切，没有勾线的细结构交回 matting。** 这两个的短板不重叠，所以也可以串起来用。

## 它现在做不到什么

**勾线断口会漏。**

泛洪唯一的失败模式就是"线断了"。如果某个角度的勾线没画连（或者被高光、被背景色接近的填色打断），泛洪会从断口钻进去，在角色身上留下一块灰。

我实测遇到过一次，在某个动作的腿和鞋那一带。现在的做法是先对可通行区做闭运算把断口补上，但它不是万能的——**断口宽了补不上，补狠了又会把细结构连成一片。**

**所以这套东西现在的状态是：方向确定是对的，边界情况还在收。**

还有一件事得说明白：它不需要模型，也不需要 GPU，但**它假设你的素材有勾线**。没有描边的写实素材、渐变背景、多个主体，别用这个。

---

## 用法

```bash
# 单图
python line_keying.py 输入.png 输出.png

# 帧序列（自动共用同一个背景色）
python line_keying.py ./frames/ ./keyed/

# 关掉内部空腔处理，只看外部（调参时很有用）
python line_keying.py in.png out.png --no-hole-fill
```

参数只有三个值得动的，而且都很好判断：

| 参数 | 默认 | 什么时候动 |
|---|---|---|
| `--tol-out` | 30 | 背景和勾线对比不够强时放大 |
| `--seed-max` | 12 | 背景是渐变、估计不准时放大 |
| `--erode` | 1 | 边缘还留着一圈灰就加到 2 |

它跟 `pure_bg_keying.py` 一样会自己报数：背景色、切出多少像素、内部空腔切掉几块、**误挖的洞有几个**。

最后那个数字要单独说一句：它会把空腔处理**故意**切掉的区域先补回去再数洞，所以它只反映"误挖的洞"。⛔ 而且它不能单独用来判断好坏——**一个被切掉半个头的角色，也不会有洞。** 必须同时看实心面积。

## 结论（就一句）

**做图之前先问一句：这张图里有没有现成的边界可以直接用。**

我调了一整天的颜色阈值、模型交集、时域平滑，全都是在**我假设的边界**上做文章。而边界本来就在那儿，是画上去的。
